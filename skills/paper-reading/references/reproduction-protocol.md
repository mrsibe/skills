# 论文复现协议（Reproduction Protocol）

## 先声明复现目标

| 类型 | 目标 | 验收标准 |
| --- | --- | --- |
| 官方实现运行（rerun） | 原仓库在指定环境正常运行 | 可得到可追踪的输出和日志 |
| 独立重实现（reimplementation） | 不照搬核心代码，按论文重新实现 | 算法行为和基础单元测试一致 |
| 结果复现（results reproduction） | 尽可能重现论文的主要指标 | 在原设定与明确容差内接近结果 |
| 核心机制验证（concept test） | 用小数据/玩具环境测试关键想法 | 能区分有无该机制的效果 |

若用户算力不明确，优先建议 **核心机制验证**，不要直接给出昂贵的完整训练计划。

## 阶段一：可复现性信息收集

逐项记录：

- 论文及版本；代码仓库、commit/tag、许可证。
- 数据来源、使用许可、切分方式、预处理与过滤。
- 软件：Python/PyTorch/CUDA 等关键版本；随机种子。
- 硬件：GPU 型号、数量、内存、网络；估计训练预算。
- 超参数：批量、学习率、调度、训练步数、精度、长度、搜索空间。
- 评估：指标计算公式、批量设定、解码/采样策略与方差报告。
- 环境差异、缺失信息与无法复现的部分。

## 阶段二：构造最小实验

1. 写出**唯一核心假设**（示例：组件 X 降低了 rollout error）。
2. 明确相同资源下的对照：`baseline` vs `baseline + X`。
3. 选择可控的小数据或玩具环境，先验证功能正确性。
4. 定义自变量、受控变量、评价指标、随机种子数量与停止条件。
5. 明确预期结果及**否证条件**；不要在看完结果后随意更改假设。
6. 单元测试形状、随机性、数值稳定性、边界条件和泄漏风险。

## 阶段三：执行与记录

```markdown
# Experiment Log
- Date / Commit / Environment：
- Paper / Version：
- Hypothesis：
- Baseline：
- Change：
- Dataset / Split：
- Seeds：
- Compute budget：
- Metrics & Evaluation Protocol：
- Actual results：<未执行时填写“未运行”>
- Differences from paper：
- Unexpected behavior：
- Next experiment：
```

## 阶段四：解释结果

- 区分“代码正确运行”和“科学结论复现”。
- 任何数值都说明来源：原论文、作者仓库、自己实测或预测。
- 未能对齐原论文结果时先检查数据、评价协议、超参、随机性和计算预算。
- 负结果同样需要记录；不要悄悄改变实验直到得到想要的结论。
- 给出下一轮最能减少不确定性的实验。
