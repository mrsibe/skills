# 审查清单与症状对照

用于审查现有界面、验收改动，或在没有明确投诉时定位问题。**按顺序检查**：前一组不通过时，后面组的结论会被结构问题污染。

每项都给出可判定的标准，避免「感觉不对」这类无法收敛的意见。

---

## A. 层级（最先检查）

| 检查项       | 通过标准                                             | 不通过的表现                   |
| ------------ | ---------------------------------------------------- | ------------------------------ |
| 主次可分     | 眯眼/模糊看页面，仍能分出 1 个主信息、若干次信息     | 所有元素同等显眼，页面像一堵墙 |
| 通道分工     | 层级不只靠字号；字重与颜色各承担一部分               | 主标题巨大、次要文字极小       |
| 文字颜色数   | ≤3 种                                                | 4 种以上灰色，无法对应重要性   |
| 字重数       | 2 种（+ hover 态例外）                               | 同一层级混用 400/500/600       |
| 弱字重       | 正文 ≥400                                            | 小字号用 300 及以下            |
| 彩色背景文字 | 与背景同色相、手动调出的颜色                         | 灰色文字 / 白色 + opacity      |
| 强调方式     | 靠弱化竞争者获得突出                                 | 目标元素颜色越加越多           |
| 操作分级     | 页面只有 1 个主按钮；次操作用描边/低对比；三级用链接 | 所有按钮实心，或全部一样大     |
| 破坏性操作   | 非主操作时用次/三级样式，强化样式留给确认弹窗        | 每个删除按钮都又大又红         |
| 标签使用     | 能从格式或上下文识别身份时不用标签                   | 满屏 `字段：值` 两列结构       |
| 语义标签     | 标题的视觉大小按重要性定，而非按 `h1`–`h6`           | 区块标题比内容更抢眼           |

## B. 间距与布局

| 检查项     | 通过标准                                   | 不通过的表现                                      |
| ---------- | ------------------------------------------ | ------------------------------------------------- |
| 留白量     | 元素周围留白偏宽而非偏紧                   | 元素贴边、内容挤在一起                            |
| 取值来源   | 所有间距来自阶梯（4/8/12/16/24/32/48/64…） | 出现 17/22/29 等一次性值                          |
| 取值种类   | 单页不同间距值 ≤8 种                       | 十几种，肉眼难辨差异                              |
| 分组清晰   | 组内间距 < 组间间距                        | 表单里 label 离上一个 input 比离自己的 input 更近 |
| 列表节奏   | 条目间距 ≠ 行高                            | 列表看起来像一段连续文字                          |
| 宽度       | 内容区按需要收窄，用 `max-width` 限上界    | 正文拉满 1440px 宽                                |
| 通栏一致性 | 通栏是内容需要，不是「因为导航通栏」       | 所有区块被迫同宽                                  |
| 弹性元素   | 侧边栏等用固定宽度，主区弹性               | 侧边栏随屏幕变宽/被压到不可读                     |
| 无反向缩放 | 元素不会在中等屏比大屏更宽                 | 栅格百分比导致的倒挂                              |
| 响应式起点 | 小屏布局先成立，大屏是增强                 | 桌面版压缩后在小屏堆叠                            |

## C. 排版

| 检查项   | 通过标准                           | 不通过的表现                      |
| -------- | ---------------------------------- | --------------------------------- |
| 字号来源 | 来自 5–11 档阶梯                   | 出现 13/15/17/19px                |
| 字号数量 | 单页 ≤6 档                         | 8 档以上                          |
| 单位     | 字号用 px/rem                      | 用 em 定义阶梯，嵌套后得到 17.5px |
| 行长     | 45–75 字符（20–35em）              | 正文跨越整个屏幕                  |
| 行高     | 随行长增大、随字号减小             | 全站统一 1.5；大标题也 1.5        |
| 基线对齐 | 同行混排字号按基线对齐             | 垂直居中导致基线错开              |
| 对齐     | 左对齐为主；仅短文本居中           | 多行段落居中、两端对齐未开断词    |
| 数字     | 表格数字右对齐                     | 数字居中/左对齐，无法比较         |
| 链接     | 密度越低越显眼；边缘链接可仅 hover | 页面里所有文字都带下划线颜色      |
| 字距     | 未改动，或仅对大标题/全大写微调    | 全大写小字用默认字距              |

## D. 颜色

| 检查项     | 通过标准                             | 不通过的表现                       |
| ---------- | ------------------------------------ | ---------------------------------- |
| 灰阶数量   | 8–10 阶可用                          | 只有 3 阶，被迫在近似灰之间妥协    |
| 色阶来源   | 预定义                               | `lighten()`、`rgba` 叠加、临时调色 |
| 饱和度     | 浅阶/深阶饱和度同步提高              | 浅色发白、深色发闷                 |
| 品牌色克制 | 主色用于操作与激活态，不是大面积填充 | 每张卡片都是品牌色背景             |
| 语义一致   | 同一含义全站同色                     | 有的地方红色是错误，有的地方是强调 |
| 对比度     | 正文 ≥4.5:1，大字 ≥3:1               | 浅灰小字叠在彩色背景上             |
| 非颜色冗余 | 状态除颜色外有图标/文字/形状         | 只有红绿两色区分涨跌               |
| 图表辨识   | 靠明暗与线型区分系列                 | 仅靠五种相近色相                   |

## E. 层次感

| 检查项   | 通过标准                                   | 不通过的表现                                 |
| -------- | ------------------------------------------ | -------------------------------------------- |
| 阴影数量 | ≤5 档，且对应明确层级                      | 每个组件随手写一个 `0 0 10px rgba(0,0,0,.1)` |
| 高度语义 | 越高层的元素阴影越大（模态 > 菜单 > 卡片） | 卡片阴影比模态还重                           |
| 双层     | 重要浮层使用双层阴影                       | 单层大模糊，边缘虚散                         |
| 光的方向 | 凸起上亮下影，凹陷下亮内影                 | 上下都亮、或四边均匀描边                     |
| 边框替代 | 优先用间距/背景色/阴影分区                 | 满屏 1px 灰边框                              |
| 重叠     | 关键区块有跨背景、超容器或图片重叠         | 所有内容都严格包在容器里                     |

## F. 图片与内容

| 检查项      | 通过标准                        | 不通过的表现                 |
| ----------- | ------------------------------- | ---------------------------- |
| 位图尺寸    | 不放大超原始尺寸                | 截图被拉到 2 倍显示          |
| 图标尺寸    | 图标接近其设计尺寸（16–32px）   | 24px 图标放大到 96px         |
| 截图        | 用合适尺寸的截图或局部截图      | 全屏截图塞进小卡片           |
| 图内文字    | 有蒙版/降对比/光晕，对比度稳定  | 白字压在亮部消失             |
| 用户上传    | 固定容器 + `cover` 裁切，防渗色 | 原始比例打乱布局             |
| 空状态      | 有插图 + CTA，无用控件隐藏      | 空页面只有一行灰字           |
| 加载/错误态 | 与正常态视觉一致                | 空表格 vs 有数据表格结构不同 |

## G. 打磨（最后做）

- 项目符号、引用、链接、checkbox/radio 是否还是浏览器默认样式？
- 有没有可以用强调色边框提升的平淡区块（卡片顶部、激活导航、提示条）？
- 背景是否过于单一（可换色、渐变、低对比图案）？
- 是否所有组件都用了最保守的形态（下拉、表格、radio 有改造空间）？

## 症状 → 病因

| 症状             | 最可能的原因                       | 优先读            |
| ---------------- | ---------------------------------- | ----------------- |
| 「看起来像模板」 | 没有层级，全站一个音量             | principles §2     |
| 「很挤」         | 留白是加出来的，只到下限           | principles §3     |
| 「乱」           | 间距/字号未收敛到阶梯              | tokens §1–2       |
| 「土」           | 纯灰 + 纯黑 + 默认衬线/系统字体    | principles §5     |
| 「廉价」         | 只有一个阴影档、满屏边框、默认控件 | principles §6, §8 |
| 「读不下去」     | 行长过宽、行高恒定、对比度不足     | principles §4     |
| 「重点不突出」   | 主操作为零或为三                   | principles §2     |
| 「花」           | 颜色只靠色相区分、品牌色大面积使用 | principles §5     |
| 「不像做完了」   | 空状态、加载态、边缘情况未设计     | principles §8     |
| 「说不清哪里怪」 | 分组间距含糊，组内 ≥ 组间          | principles §3     |

---

## 验收方式

改完后至少确认三件事，缺一不可：

1. **缩小到 50% 或眯眼看**：层级是否还在。
2. **换真实内容**：用最长文案、0 条数据和 200 条数据各看一次。
3. **代码里搜裸值**：颜色、字号、间距、阴影是否都来自体系。

无法渲染验证时，明确说明哪些结论只来自代码审查。
