# 规则明细：原因、做法与反例

按主题组织。每条规则给出「怎么做」「为什么」「常见错误」。与 `SKILL.md` 中的流程配合使用：定位到某个主题后，只读对应小节。

---

## 1. 设计过程：从功能开始，不从外壳开始

**从真实功能开始，而不是从页面骨架开始。**

导航、侧边栏、容器宽度这些「外壳」决定的依据是功能的形状。功能还没设计出来就定外壳，只能靠猜。

**早期刻意降低保真度。**

- 纸面 + 粗马克笔草图：物理上无法抠细节，只能比较布局。
- 灰阶起步：只靠间距、大小、对比度撑住画面，逼出层级；上色是之后的事。
- 草图和线框图是一次性的，做出决定就丢掉，不要维护。

**小步循环，而不是一次设计完。**

设计一个功能的最小版本 → 立刻实现 → 在真实界面里改 → 再做下一个功能。凭空想象 2000 条数据的界面、错误提示位置、时间冲突的日历，比对着能跑的版本改要难得多。

**悲观设计：只设计能交付的部分。**

给功能加一个「锦上添花但可能做不完」的区块，风险是整个功能都无法交付。先交付没有附件功能的评论区，比交付不了评论区好。

**先定个性，再定细节。**

个性由四件具体的事决定，不是抽象感觉：

| 通道 | 偏向一端              | 偏向另一端                           |
| ---- | --------------------- | ------------------------------------ |
| 字体 | 衬线 → 优雅、经典     | 圆润无衬线 → 活泼；中性无衬线 → 朴素 |
| 颜色 | 蓝 → 安全、熟悉       | 金 → 昂贵；粉 → 轻松                 |
| 圆角 | 直角 → 严肃、正式     | 大圆角 → 活泼                        |
| 文案 | 正式措辞 → 官方、专业 | 口语化 → 亲切                        |

一致性比方向重要：同一界面里混用直角与圆角，几乎总比坚持其中一种更差。参考目标用户的同类产品（正经生意 / 活泼品牌），但不要照搬直接竞品，否则会像别人的低配版。

**限制选项：先定体系，再选值。**

从无限取值里挑「最好的一个」为什么折磨人？因为正确答案永远不止一个。可选值都很合理时，决策没有终点。解决办法不是提高审美，而是**缩小候选集**：预设 8–10 个色阶、一条字号阶梯，从此只从里面挑。

**用排除法做选择。** 有了体系后，选值变成比较而不是创作：

1. 从阶梯里猜一个最合适的（比如图标 16px）。
2. 把它两侧的档位摆出来对比（12px 与 24px）。
3. 如果两侧都明显更差，中间那个就是唯一解，结束。
4. 如果某一侧更好，就把它当作新的「中间值」，再比一轮。

前提是相邻档位差异足够明显（≥25%）——这正是尺寸阶梯要遵守相对差的原因。

**值得体系化的东西**：字号、字重、行高、颜色、外边距、内边距、宽度、高度、盒阴影、圆角、边框宽度、不透明度。原则：

- 不要求一次全定好，但每做一个新决定都要问「这是不是一个该进体系的取值」。
- 同一个小决定不值得做第二次。

## 2. 视觉层级

**层级 = 关键元素与其余元素的对比度差，而不是元素本身的美化。**

当所有元素都在争取注意力，界面读起来像一面贴满内容的墙；刻意压住次要和三级信息，即使配色、字体、布局都不变，观感也会立刻不同。

**不要用字号承担全部层级。**

只用字号会导致主内容过大、次要内容过小。把「更重要」分给字重或颜色，字号才能回到合理区间。

**限定通道数量，才能形成系统。**

- 文字颜色 3 种：深色为主内容，中灰为次要，浅灰为三级。
- 字重 2 种：常规（400/500）+ 强调（600/700）。
- 避免 <400：小字号下可读性差。想弱化就用更浅的颜色或更小的字号，不要用更细的字重。

**彩色背景上不要用灰色文字。**

灰字的弱化效果来自「与背景对比度降低」，而灰色与彩色背景的色相不匹配，看起来发脏。正确做法：取背景色的色相，调饱和度和明度，手动挑一个更接近背景的颜色。

不要用「白色 + 降低不透明度」代替：结果发闷、像禁用态，叠在图片上还会透出背景。

**弱化竞争者，而不是强化目标。**

目标元素已经用了强调色但还不够突出时，继续加码会破坏层级。改为压住和它竞争的元素（未激活项用更柔和的颜色、侧边栏不要单独背景色）。

**标签是最后手段。**

1. 格式能否说明身份？（`janedoe@example.com`、`(555) 765-4321`、`$19.99`）
2. 上下文能否说明？（员工名录里名字下方的 `Customer Support` 就是部门）
3. 能否把标签合进值？（`In stock: 12` → `12 left in stock`；`Bedrooms: 3` → `3 bedrooms`）
4. 必须加标签时，把它降为辅助：更小、更低对比、更轻。用户确实在**找标签**的场景（技术规格页）反过来处理，但值也不要压得太狠。

**语义标签不要决定视觉大小。**

`h1` 用来标记页面标题在语义上是对的，但这不意味着它该很大；界面里的区块标题多数是标签属性。可以保留语义标记、视觉上隐藏，靠内容本身表达层级。

**字重与对比度的配重关系。**

粗体比常规体显眼，因为它覆盖的像素面积更大。同一条规律适用于所有「重」的元素：

- 图标（尤其实心图标）天然比文字重，且无法改字重 → 降低对比度来配平。
- 低对比度的 1px 细边框不显眼时，把边框加粗，而不是把颜色加深（加深会让界面变脏）。

**操作按钮按重要性分级，而不是按语义分级。**

- 主操作：实心、高对比背景，一屏通常只有一个。
- 次操作：描边或低对比背景，清晰但不抢眼。
- 三级操作：链接样式，可被发现但不打扰。

破坏性操作不会因为破坏性强就该又大又红——它是次操作时就用次操作样式，把强化样式留给确认弹窗里的那一个按钮。

## 3. 间距与布局

**留白用减法。**

加出来的留白只到「不至于难看」的下限。正确顺序：先给远多于需要的空间，再往下减。单独看某个元素觉得「稍微多了一点」时，放进整页语境通常正好。

紧凑界面有正当场景（仪表盘需要一屏看到大量信息），但必须是刻意决定，不能是默认结果。

**线性阶梯无效。**

「一切都是 4 的倍数」不能帮你在 120px 和 125px 之间做决定。体系必须体现**相对差**：小尺寸端 12→16 是 33%，一眼可辨；大尺寸端 500→520 只有 4%，看不出来。所以阶梯在小端密集、大端稀疏，相邻档位相对差 ≥25%。

**用基准值推阶梯。**

16px 起步（能整除、是浏览器默认字号），用它的因数与倍数展开：`4, 8, 12, 16, 24, 32, 48, 64, 96, 128…`。具体数值见 `tokens.md`。

在浏览器里写代码比在画布上拖更容易坚持体系——这也是优先在代码里改样式的理由之一。

**不要填满屏幕。**

需要 600px 就用 600px。摊开或拉宽只会降低可读性。不要因为导航是通栏的，就把所有东西做成通栏。反过来说，需要大空间就用，只是不必为填满而填满。

**从窄画布开始设计响应式。**

先按约 400px 设计移动端，再放大到桌面。小屏上觉得「将就」的地方，到桌面端往往只需要很少调整。

**窄内容在宽容器里失衡时，拆栏而不是拉宽。**

表单 + 说明文字：把说明拆到独立一栏，比把表单拉宽更好。

**栅格被高估。**

栅格本质上强制元素用弹性百分比宽度。很多元素需要固定宽度：

- 侧边栏：给按内容优化的固定宽度，主内容区弹性填满剩余空间（并在内部用自己的栅格）。
- 组件内部：除非确实要跟着缩放，不要用百分比定尺寸。
- 登录卡片这类有最佳宽度的元素：给 `max-width`，只有屏幕比它还窄时才收缩。

反例：栅格会让登录卡片在中等屏幕上比大屏幕上更宽，因为栏宽是弹性的。

**相对尺寸不能通用。**

把标题写成正文的 2.5em，在桌面端可能完美；到小屏把正文缩到 14px，标题就变 35px。而小屏合适的标题是 20–24px，即正文的 1.5–1.7 倍——**两者之间不存在固定比例**。

一般规律：大屏上大的元素，到小屏要缩得更快；小屏上不同元素的差距应该被压缩。

组件内部同理：按钮内边距不该与字号等比。大按钮的内边距应更宽松，小按钮更紧，这样才「像」大按钮和小按钮，而不是整体缩放。

**避免含糊的间距。**

只要靠间距来分组，就必须保证**组内间距 < 组间间距**：

- 表单：label 与 input 之间小，两组之间大——否则用户会把值填进错字段。
- 文章：区块标题上方空间要明显大于标题与正文之间的空间。
- 列表：条目间距不要刚好等于行高。
- 横向排列同理。

## 4. 排版

**建立字号阶梯，不要逐像素调。**

界面里常见 10–24px 每个整数都被用到。这既不一致，也拖慢决策。两种做法：

- **模数阶梯**（4:5、2:3、1.618）：数学上优雅，但会产生 31.25px 这类小数，且跨度对界面往往太粗——你会需要在 12 和 16 之间再加一档。
- **手工阶梯**：直接挑值，控制权在自己手里，界面设计更实用。推荐 `12, 14, 16, 18, 20, 24, 30, 36, 48, 60, 72`。

**用 px 或 rem 定义阶梯，不要用 em。**

em 相对当前字号，嵌套后算出的值会掉出阶梯（1.25em 元素内部的 .875em 得到 17.5px）。

**选字体：**

- 稳妥选择是中性的无衬线；系统字体栈是安全牌。
- 忽略字重少于 5 种的字体——字重齐全通常意味着做得更用心（Google Fonts 按样式数 ≥10 筛选，能砍掉大部分选项）。
- 正文不要用为标题设计的字体（x 高度小、字距紧），小字号下难读。
- 按流行度排序是有效的集体判断，尤其在挑有味道的展示字体时。
- 从设计精良的网站「偷」字体，往往是稳妥方法找不到的好选择。

**控制行长。**

每行 45–75 个字符（含空格），约 20–35em。超过 75 属于高风险区。段落要和宽元素混排时，仍限制段落宽度——同一内容区里用不同宽度，看起来更精致。

**按基线对齐，不要垂直居中。**

同一行混用不同字号时，垂直居中会让基线错开，字号差越大越明显。按字母坐落的基线对齐即可。

**行高讲究比例。**

- 与行长成正比：窄内容 1.5，宽内容可到 2。
- 与字号成反比：小字需要更大行高帮助换行定位；大标题 1–1.2 就够，甚至不需要额外行距。

**链接的强调强度取决于密度。**

- 段落中的孤立链接：必须明显（颜色 + 下划线）。
- 界面里几乎所有东西都是链接：用更含蓄的方式（更重的字重、更深的颜色）。
- 边缘路径上的链接：可以只在 hover 时加下划线或变色。

**对齐：**

- 默认左对齐（与书写方向一致）。
- 居中只适合大标题或 2–3 行内的短文本；更长就重写文案缩短，而不是换对齐方式。
- 数字右对齐，让位数对齐后可扫读。
- 两端对齐必须同时开断词，否则词间空隙难看。

**字距：默认不要动，两种例外。**

- 用字距较宽的字族做大标题时，收紧字距，模仿标题字族的紧凑感。
- 全大写文字加大字距：全大写缺少上伸部/下伸部的形状差异，默认字距下更难分辨。

反过来不成立：标题字族即使加大字距，小字号下也很少可读。

## 5. 颜色

**用 HSL 思考，而不是 hex/RGB。**

hex 里视觉上接近的两个颜色在代码里看不出关系。HSL 的三个分量对应人眼直觉：色相（色轮位置，0° 红 / 120° 绿 / 240° 蓝）、饱和度（0% 灰 → 100% 浓烈）、明度（0% 黑 → 50% 最纯 → 100% 白）。

注意 HSL 与 HSB 不同：设计软件多用 HSB，浏览器只认 HSL。HSB 100% 亮度 + 100% 饱和度 ≈ HSL 50% 明度。

**需要的颜色比多数人以为的多。**

配色生成器给的 5 个颜色做不出真实界面。一套调色板分三类：

| 类别        | 数量                       | 用途                                                 |
| ----------- | -------------------------- | ---------------------------------------------------- |
| 灰阶        | 8–10 阶                    | 文字、背景、面板、表单控件——界面主体几乎全是灰       |
| 主色        | 1 个（最多 2 个），5–10 阶 | 主操作、激活态导航；决定网站整体观感                 |
| 强调/语义色 | 数个，各 5–10 阶           | 警告黄、破坏红、正向绿；区分图表折线、日历事件、标签 |

复杂界面出现「10 种颜色 × 5–10 阶」是正常的。

**色阶必须预定义。**

不要用 `lighten()`/`darken()` 或临时调不透明度生成变体——这是「35 个略有差异、看起来一样的蓝色」的成因。

**基础色不要从公式来。**

- 基色：选一个适合当按钮背景的中间调。没有「必须从 50% 明度开始」的规则，靠眼睛。
- 两端：最深阶通常用于文字，最浅阶用于背景染色。用一个提示框组件（同时需要这两种用途）来定这两个值。
- 中间：补齐 9 阶骨架 900/500/100，先定 700 和 300，再补 800/600/400/200。
- 灰色系流程相同，基色不重要；最深灰给最深文字，最浅灰给微妙的浅色背景。

系统化只是起点：真正用起来后按眼睛微调饱和度与明度，但不要频繁新增色阶——不严格约束的话，等于没有体系。

**明度会吃掉饱和度。**

HSL 里明度越接近 0% 或 100%，饱和度的影响越弱。所以浅阶和深阶都要提高饱和度，否则会发灰发白。差别细微，但大面积使用时会累积。

**感知亮度不是明度。**

黄色和蓝色在 HSL 明度相同时，人眼觉得黄色更亮。色相的感知亮度不是线性变化：低点在红、绿、蓝，高点在黄、青、品红。

**用旋转色相改亮度，而不是只压明度。**

只调明度会让颜色更接近白或黑，损失浓烈感。想让颜色更亮，把色相转向最近的亮色相（60°/180°/300°）；想更暗，转向最近的暗色相（0°/120°/240°）。

典型场景：黄色系的深色阶往下转橙，才不会发闷发褐。也可以两种办法混用（一部分靠色相、一部分靠明度）。**幅度控制在 20–30° 内**，超过就是换了个颜色。

**灰色不一定灰。**

纯灰饱和度 0%，会给界面一种中性但偏冷的观感。给灰加一点蓝 → 冷；加一点黄/橙 → 暖。浅阶和深阶也要同步提高饱和度，否则相对中间阶会显得发白。加多少是风格选择。

**无障碍与美观不冲突。**

- WCAG：正文对比度 ≥4.5:1；大字号（≥24px 常规或 ≥19px 粗体）≥3:1。
- 深色背景 + 白色文字常常需要背景深到抢走注意力 → **反转对比**：浅背景 + 深文字，颜色还在，但不再压过页面其他操作。
- 彩色背景 + 彩色文字：只调明度和饱和度很难达标 → 把文字色相朝更亮的色相（青、品红、黄）旋转。
- 不要只靠颜色传达信息：加图标、形状或图案；图表用明暗对比而不是不同色相，色盲用户分辨明暗比分辨色相容易。

## 6. 层次感

**光从上方来。**

这是唯一需要记住的物理规律，凸起与凹陷都由它推出：

- **凸起**：上沿朝上 → 更亮（上边框或正向内阴影）；下沿背光 → 藏起来；下方加小范围、垂直略偏移的**深色外阴影**（模糊小、边缘偏锐）。浅色高光要手动挑颜色，不要用半透明白（会吸走底层颜色的饱和度）。
- **凹陷**：只看得到下沿 → 下沿更亮；上方边缘挡住光 → 顶部加小范围深色内阴影，垂直偏移要保证它不从底部透出。

同类元素（输入框、复选框、凹槽面板）共用这套处理。不要追求照片级写实，界面会变脏。

**阴影 = z 轴高度。**

模糊半径与范围决定元素「离用户多高」，越高越抓注意力：

- 按钮 / 卡片：小阴影（需要被注意到，但不抢整个页面）。
- 下拉菜单 / 悬浮面板：中等阴影。
- 弹窗 / 模态：大阴影。

**建立 5 档高度体系**，先定最小与最大，中间大致线性补齐。选阴影时不要想阴影本身，先想「这个元素该在 z 轴的哪一层」。

**阴影也是交互语言。**

- 拖动中的列表项抬起 → 加阴影。
- 按钮按下 → 减小或去掉阴影（被按进页面）。

**双层阴影更可控。**

- 外层：大而柔、垂直偏移大、模糊大 —— 模拟直射光投下的影子。
- 内层：小而暗、偏移小、模糊小 —— 模拟物体下方连环境光都照不到的接触区。

**高度越高，内层阴影越轻**（物体离表面越远，接触遮蔽越弱）。

**扁平设计也能有层次。**

- 颜色：比背景**浅**显得浮起，比背景**深**显得凹陷。
- 实心阴影：不模糊、仅垂直偏移的短阴影，适合卡片和按钮。

**重叠是最有效的深度手段。**

让元素跨两个背景的交界、超出父容器边界、控件压在轮播图角落。图片重叠时加一圈与背景同色的「隐形边框」，保证彼此之间留有缝隙。

---

## 7. 图片

**照片质量是硬门槛。**

要么请专业摄影，要么用高质量图库。不要用占位图设计再指望事后替换——这几乎从不成立。

**图片上的文字：先降图片动态范围。**

问题不在文字颜色，而在图片同时有极亮和极暗区域。四种处理，可组合：

1. 叠半透明蒙版（黑蒙版压亮部配浅字，白蒙版提暗部配深字）。
2. 降低图片对比度（记得补亮度）。
3. 给图片着色：降对比 → 降饱和 → 叠纯色「multiply」。
4. 给文字加**无偏移、大模糊**的光晕阴影（不是真正的投影）。

**每张图有它该有的尺寸。**

- 位图不放大。
- 16–24px 的图标不放大 3–4 倍：矢量不糊，但细节不足、显得笨重。把图标装进带背景色的形状里，让它保持接近设计尺寸。
- 全屏截图不要缩到小容器里（16px 文字变 4px）。改用更小屏的截图、局部截图，或画一张去掉细节的简化界面。
- favicon 按目标尺寸重画极简版，不要让浏览器缩。

**用户上传的内容要设容器。**

- 固定尺寸容器 + `background-size: cover` 裁切，避免原始比例破坏布局。
- 防止背景渗色：用轻微内阴影，或半透明内边框；硬边框容易和图片内容打架。

## 8. 打磨

**先升级默认样式，而不是加新元素。**

- 项目符号 → 图标（对勾、箭头，或贴合内容的图形）。
- 引用符号放大、换色，当成视觉元素。
- 链接：自定义粗下划线（可与文字轻微重叠）。
- checkbox / radio 用品牌色自绘。

**强调色边框。**

沿卡片顶部、当前导航项、提示消息侧边、大标题下方的一小段、或整个页面顶部加彩色条。不需要平面设计功底，但观感提升明显。

**背景装饰。**

- 换背景色区分面板或页面区域。
- 渐变：两个色相差 ≤30°。
- 低对比重复图案（可只沿一条边重复）。
- 单独的几何形状、图案切片或简化的插画。

对比度压低，别干扰内容。

**空状态是优先项。**

依赖用户生成内容的产品，空状态是新功能的第一印象。「精选数据」很漂亮，真实用户点进去看到白板，产品就毁了。做法：插图吸引注意 + 突出 CTA；把暂时无用的辅助 UI（tab、筛选器）隐藏起来。

**少用边框。**

分区优先考虑：阴影（在元素与背景颜色不同时最有效）→ 相邻元素不同背景色 → 直接加大间距。已用不同背景色还加边框时，试着去掉边框。

**跳出组件成见。**

组件的外形是惯例不是规则：下拉菜单可以多列、分组、带辅助文字和彩色图标；表格可以合并无需排序的列、加入图片或颜色；一组重要的 radio 可以做成可选卡片。

## 9. 持续改进

- **留意自己不会做的决定**：看到喜欢的设计时问「这位设计师做了什么我根本想不到的事」。
- **重建喜欢的界面**：不看开发者工具，从头重做一遍，差异会逼出具体技巧（收紧标题行高、给全大写加字距、叠两层阴影）。
- **把发现写回体系**：新技巧只有变成规则或 token 才算学到。
